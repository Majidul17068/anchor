# Anchor — architecture

Product name: **Anchor**. Tagline: *Your Antigravity, anchored to you.*
App id `com.anchor.desktop`, Go module `github.com/Majidul17068/anchor`,
UI bridge `window.anchorBridge`.

Anchor is a desktop client for Google's Antigravity CLI (`agy`) in the
spirit of OpenClaw: a native app on top of a CLI you already have, with your
own Google account for auth and your own Google Drive for storage. Nothing
is hosted by Anchor.

## Stack

| Layer | Choice | Why |
|---|---|---|
| Shell | Wails v2 (Go + system webview) | one static binary per OS, small installers, Go for process control |
| Backend | Go 1.27 | spawns and speaks to `agy`, SQLite without cgo, official Google API clients |
| UI | React 19 + TypeScript + Vite + Tailwind + zustand | generated as a POC in Google AI Studio, kept as is |
| Model access | `agy acp` (Agent Client Protocol v1 over stdio) | Google's documented integration surface; the CLI's own Google login applies |
| Local data | JSON files under `~/.anchor` | sessions metadata, transcript cache, device id, settings |
| Sync | Google Drive `appDataFolder` | per-user, hidden, free, no server |
| Marketplace | public GitHub repo with `index.json` | searchable catalog without hosting |

## Verified facts about the CLI (2026-11-11, agy 1.5.5)

- `agy acp --stdio` answers `initialize` with capabilities: `loadSession`,
  `sessionCapabilities.{resume,close,load,list}`, `auth.logout`,
  `_meta.antigravity.tier`, `promptCapabilities.{image,embeddedContext}`.
- `session/new` returns models, modes (`default`, `accept-edits`, `auto`,
  `plan`), `configOptions` (`model`, `thought_level` low/medium/high,
  `mode`) and `_meta.antigravity.tier` = `{name:"Google AI Pro", id:"g1-pro-tier"}`.
- `session/list` returns `{sessionId, cwd, title, updatedAt}` for every
  conversation on the machine (paged with `cursor`).
- `session/load` replays history as `session/update` notifications
  (`user_message_chunk`, `agent_message_chunk`, `agent_thought_chunk`,
  `tool_call`, `tool_call_update` with `rawInput`/`rawOutput`/`content[diff]`),
  then returns the setup result. `session/resume` attaches without replay.
- `session/prompt` streams the same notifications and returns
  `{stopReason, usage}`; `session/cancel` yields `stopReason: cancelled`.
- `session/request_permission` is an agent→client request with
  `options[{optionId, name, kind}]`; answer `{outcome:{outcome:"selected",optionId}}`.
- Auth methods: `oauth-personal`, `oauth-business`, `gemini-api-key`,
  `agent-platform`. Error `-32000` means sign-in required.
- Skills: `<root>/skills/<name>/SKILL.md` with YAML `name`/`description`;
  global root `~/.gemini/config/`. Plugins: `~/.gemini/config/plugins/<p>/{skills,agents}`.
  Builtin skills: `~/.gemini/antigravity-cli/builtin/skills`. Skills show up
  as slash commands in `available_commands_update`.
- Full-text index: `~/.gemini/antigravity-cli/conversation_summaries.db`
  (FTS5 table `conversations_fts`), readable while the CLI runs.

## Bridge mechanics

- Request/response calls: `window.go.main.API.<Method>(...)` → Promise.
  Rejections are wrapped in `Error` so the UI's `err.message` checks work
  (for example `NOT_PARENT_SOURCE`).
- Streams become Wails events. The UI subscribes first, then calls:
  `chat:<streamId>` (ChatEvent until `done`), `cli:install`
  (InstallProgress until `done`), `skills:eval:<id>` (EvalEvent until `done`),
  `sync:status` (SyncStatus), `sessions:changed` (refresh hint).
- In a plain browser `window.go` is absent and the mock bridge is used.

## Session lifecycle

1. **List**: `session/list` ∪ `~/.anchor/sessions/*.json`. Unknown CLI
   conversations get metadata (origin = this device). Local records whose
   CLI conversation vanished are dropped unless they are replicas.
2. **Open**: cached transcript if fresh; otherwise `session/load` rebuilds
   it silently and caches it (`CachedAt`).
3. **Prompt**: `session/resume` (or `session/new` for a replica that never
   ran here, seeded with the transcript as an embedded resource), apply
   `model`, `thought_level`, `mode`, then `session/prompt`. Notifications map
   to `Step`s: agent chunks merge into one bubble until a tool call or
   thought interrupts; tool calls track status/output/duration; `diff`
   content becomes a diff step (already applied by the CLI; reject reverts
   when old text is known); permission requests block on the UI's answer.
4. **Finish**: cache steps, update preview/count, emit `done` and
   `sessions:changed`.

Effort: the UI offers low/medium/high because that is what ACP exposes.
Modes: `default` (ask), `plan`, `auto`, `accept-edits`.

## Sync (parent source)

- Each install has a `deviceId`; a session's `originDeviceId` never changes.
- Only the parent flips `syncEnabled`. Enabled → canonical
  `session-<id>.json` in appDataFolder; disabled → file deleted; replicas
  keep a read-only local copy marked unpublished.
- Replicas pull every 30 s and on demand; their new steps go to
  `session-<id>.append-<device>.json`. The parent merges appends by time.
- If both sides moved since the last merge, the session is flagged
  `conflict`; the parent chooses *parent wins* or *merge*.
- Devices announce themselves as `device-<id>.json`.

## Skills, agents, sharing, marketplace

- Mine/Acquired/Shared skills live in `~/.gemini/config/skills/<slug>`;
  Anchor keeps versions in `~/.anchor/skill-versions`, examples/shares in
  `~/.anchor/skills/<slug>.json`.
- Train = run each example in a throwaway session with the skill folder as
  cwd, then a judge turn answers PASS/FAIL. Improve = accept-edits turn that
  rewrites SKILL.md from failures; both snapshot before changing.
- Agents: `~/.gemini/config/agents/<name>.md`; a process per custom agent is
  started with `agy acp --agent <name>` on demand.
- Sharing: skill folder mirrored to Drive `Anchor/Shared skills/<slug>`,
  shared with a Google account (reader) or by link; recipients see it under
  *Shared with me* and import it.
- Marketplace: see docs/MARKETPLACE.md.

## Packaging

`wails build` per OS in GitHub Actions on a `v*` tag: macOS universal
`.dmg`/`.zip`, Windows NSIS installer + portable `.exe`, Linux `.tar.gz`.
`anchorctl` ships beside each. Optional secrets bake the Drive OAuth client
id into the binaries (docs/DRIVE_SETUP.md).

## Known gaps / next phases

- Sync and sharing need a Google OAuth client id in the build or settings.
- Marketplace moderation is by GitHub issues until a backend exists.
- Phase "action-based": scheduled runs, remote control, automations on top
  of the CLI's `schedule`/`remote-control` features.
